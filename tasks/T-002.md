# T-002 · 统一数据读取层 store.js（打卡/周报/报告改读云端+本地合并）

## 背景
数据读写分裂：`home.html` 打卡时双写 localStorage `stacy_daily_logs` + Supabase `daily_logs` 表，但 `history.html:138`、`report.html:99`、`weekly.html:249` **只读 localStorage**。换设备/清缓存后打卡历史全丢，云端 daily_logs 写了没人读。聊天记录侧 api.js 已有 `get_sessions_by_user()` 云端+本地合并的先例，打卡数据缺同样的层。

## 目标
新建 `store.js`，成为打卡数据的唯一读写入口；四个页面全部改走它。

## 实现要求
1. 新建 `store.js`，暴露全局函数（本项目无构建工具，直接 script 标签风格，参考 api.js 的写法）：
   - `getDailyLogs()` → Promise：从 Supabase `daily_logs` 按 `invite_code=ilike.<stacy_invite_code>` 拉取（limit 200，date 升序），与 localStorage `stacy_daily_logs` 按 `date` 去重合并（云端优先），返回数组并回写 localStorage 作缓存。无邀请码或请求失败时降级为纯 localStorage。
   - `saveDailyLog(data)`：把 home.html 现有 `saveTodayLog` + `syncToSupabase` 的逻辑收编进来（保持行为一致：本地按 date upsert + POST Supabase）。
2. `home.html`：删掉本页的 loadAllLogs/saveAllLogs/syncToSupabase 实现，引入 store.js 改调用（渲染逻辑不动，注意现有代码是同步读，改造处加 async/await 或先渲染本地再刷新）。
3. `history.html`、`report.html`、`weekly.html`：读取处改为 `await getDailyLogs()`。weekly 的自然周筛选逻辑（周一至周日）不动。
4. Supabase `daily_logs` 表若缺唯一约束导致重复行，读取端按 `(date)` 去重即可，不改表。

## 涉及文件
- 新建 `store.js`
- `home.html` `history.html` `report.html` `weekly.html`（各页 `<script src="store.js">` 引入）

## 禁区
- **种子数据保护**：weekly.html 的种子守卫逻辑不动；store.js 回写 localStorage 缓存属于"合并后回写"，必须保证不会用空数组覆盖非空本地数据
- 不动聊天记录侧（stacy_logs / api.js）
- 不改 Supabase 表结构
