# T-001 · daughter.html 亲属端按用户过滤聊天记录（隐私修复）

## 背景
`daughter.html:113` 查询 `logs?select=*&order=created_at.desc&limit=20`，**没有任何 user_id 过滤**——任何打开亲属端的人看到的是全体用户最近 20 条聊天。这是隐私事故级 bug，P0。

## 目标
亲属端只能看到绑定的那位妈妈的记录。

## 实现要求
1. 进入页面时解析 URL 参数 `?code=<邀请码>`；没有参数时读 `localStorage.stacy_daughter_code`；两者都没有则显示一个输入框让亲属输入妈妈的邀请码，输入后存入 `localStorage.stacy_daughter_code`。
2. Supabase 查询改为 `logs?user_id=eq.<code>&select=*&order=created_at.desc&limit=20`。注意 `encodeURIComponent`。契约规定 `user_id` = 邀请码原值（见 CLAUDE.md：user_id = stacy_invite_code）。
3. 邀请码比较大小写问题：查询用 `user_id=ilike.<code>`（项目已知坑点，logs.user_id 存的是用户输入原值）。
4. 没有 code 时**不发起查询**，显示引导文案，不允许裸查全表。
5. localStorage 兜底路径（catch 分支）保持不动。

## 涉及文件
- `daughter.html`（仅此一个文件）

## 禁区
- 不改 Supabase 表结构 / 不动 RLS
- 不动其他页面
- 不无条件写 `stacy_logs` / `stacy_daily_logs`（种子数据保护规则）

## 验收标准（全部通过才算完成）
```bash
# 1. 查询串必须带 user_id 过滤
grep -E 'rest/v1/logs\?user_id=(eq|ilike)\.' daughter.html
# 2. 不再存在无过滤的 logs 全表查询
! grep -E 'rest/v1/logs\?select' daughter.html
# 3. 有 code 引导逻辑
grep -n 'stacy_daughter_code' daughter.html
```
浏览器手测：带 `?code=XXX` 打开只显示该用户记录；无 code 打开显示输入框且 Network 面板无 logs 请求。
