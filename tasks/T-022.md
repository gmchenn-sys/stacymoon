# T-022 · 修复「记录」页整页 JS 失效（重复声明 SyntaxError，P0 线上故障）

## 现象

线上 stacymoon.pages.dev「记录」页（history.html）**整个内联脚本块从未执行**，页面只剩静态 HTML 空壳：

- 「今日身体打卡」只有标题条，**打卡表单根本没渲染 → 用户无法打卡**
- 睡眠评分 / 情绪记录 / 高频症状 TOP3 三张图表卡全空
- 「打卡详情」永远显示静态兜底文案"还没有打卡记录"（**即使云端有数据也不显示**）
- 「Stacy 周总结」卡（T-010 接的 Jamie A4 接口）永远不出现

浏览器实测证据：`store.js` 的 `getDailyLogs` / `saveDailyLog` 是 function（外链脚本正常），但内联块里定义的 `renderCheckin` / `renderSleepChart` / `parseSummaryText` / `loadHealthSummary` **全部 undefined**。

## 根因

`history.html:553` `async function loadHealthSummary(period)` 的**形参名是 `period`**，而 `history.html:569` 又写了 `const period = _summaryPeriod;` —— 同一函数作用域内重复声明标识符，是 **parse-time SyntaxError**（`Identifier 'period' has already been declared`），**整个 `<script>` 块被引擎直接丢弃**，块内所有函数都不会定义。

T-010（commit `7033e3a`，2026-07-12）引入，线上已坏两周。因为静态空壳看起来像"还没有数据"的正常空状态，没人发现。

复现命令（能稳定报错）：

```bash
python3 -c "
import re
src=open('history.html',encoding='utf-8').read()
b=re.findall(r'<script(?![^>]*\bsrc=)[^>]*>(.*?)</script>',src,re.S)[1]
open('/tmp/h.js','w',encoding='utf-8').write(b)
" && node --check /tmp/h.js
```

## 目标

1. **修掉重复声明**：`history.html:569` 的 `const period = _summaryPeriod;` 删掉，把该函数内后续用到这个局部 `period` 的地方改用 `_summaryPeriod`（第 576 行拼 URL 处用了它，注意一并改）。**不要改形参名**，也不要改函数的对外行为。
2. **确认整块脚本恢复执行**：修完后上面的 `node --check` 必须通过。
3. **加一道防线**：新增 `scripts/check-inline-js.sh`（若无 scripts/ 目录则建），遍历仓库根目录所有 `*.html`，抽出每个无 `src` 的 `<script>` 块跑 `node --check`，任一失败则 `exit 1` 并打印文件名+错误。这样同类"整页 JS 静默失效"以后能被一条命令抓住。脚本要能独立运行：`bash scripts/check-inline-js.sh`。

## 禁区

- 不动 `store.js` / `supabase.js` / 其他页面
- 不动 `firmware/` 目录（另一条硬件线，工作区有未提交改动）
- 不改「周总结」卡的业务逻辑、缓存 key、接口地址——**只修语法错误**
- 禁止 `git add -A`：只 add `history.html scripts/check-inline-js.sh tasks/T-022.md`
